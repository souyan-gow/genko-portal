1. 全体の構成

部分役割
端末（iPhone・PC）ブラウザの中で GENKO の画面が動く。原稿用紙への割り付けや枚数の計算も、端末の中で行う
VercelGENKO の画面（プログラム）を配る場所。GitHub に新しいプログラムを置くと、自動で配り直す
Firebase AuthenticationGoogle アカウントでのログインを受け持つ
Cloud Firestore作品・章・設定を保存するデータベース。変更があると、開いているほかの端末にすぐ知らせる
GitHubプログラムの置き場所。変更の履歴も残る

それぞれの技術を選んだ理由は「技術仕様書」にまとめています。

3. 画面の一覧と行き来

画面内容
ログイン「Google でログイン」のボタンだけ。持ち主以外のアカウントは「このアカウントでは利用できません」と表示してログアウト
作品一覧作品の一覧（タイトル、枚数、章の数、最終更新）。作成・名前変更・削除・並べ替え。全作品のバックアップ
章一覧章の一覧（タイトル、枚数、文字数、最終更新）。追加・名前変更・削除・並べ替え。.txt の読み込み・書き出し
執筆本文の編集。モードの切り替え、記号入力バー、枚数・文字数・保存状態の表示。PC では左に章一覧
設定字数×行数とプリセット、自動字下げ、適用先（作品ごと／既定値）、ログアウト
ログイン → 作品一覧 → 章一覧 → 執筆
              ↓         ↓        ↓
             設定  ←─── 各画面の右上の ⚙ から開く
  • ログインすると、前回最後に開いていた章の執筆画面を直接開く
  • 画面はアドレスの「#」以降で切り替わる（例：#/works/作品ID）。スマホの「戻る」操作もそのまま使える

4. 執筆画面の配置

PC

┌──────────────────────────────────────────────────┐
│ ← 作品名／章名    [横書き｜原稿用紙]  枚数・文字数 保存状態 ⚙ │
├──────────┬───────────────────────────────────────┤
│ 章一覧    │                                       │
│ 第1話     │   本文                                 │
│ 第2話     │   （原稿用紙モード：マス目に直接入力）    │
│ ＋章を追加 │   （横書きモード：ふつうの入力欄）        │
├──────────┴───────────────────────────────────────┤
│ [記号入力バー]                                      │
└──────────────────────────────────────────────────┘

スマホ

┌────────────────────────┐
│ ← 章名   [モード切替]  ⚙ │
│   枚数・文字数 保存状態    │
├────────────────────────┤
│   本文（全画面）          │
├────────────────────────┤
│ [元に戻す][やり直し][記号…]│ ← キーボードのすぐ上
└────────────────────────┘

デザインの方針

  • 背景は生成りの紙色、本文は明朝体、操作の部品はゴシック体
  • ダークモードあり。端末の設定に自動で合わせる
  • 原稿用紙の罫線は、ライトでは淡い朱色、ダークでは淡いグレー
  • 装飾は控えめにし、本文に集中できる見た目にする

5. データの全体像

データは「ユーザー → 作品 → 章」の3段階で保存します。

ユーザー（持ち主1人分）     設定、最後に開いた章
  └─ 作品                    タイトル、並び順、作品ごとの設定
       └─ 章                 タイトル、並び順、本文、文字数
  • 本文はプレーンテキストで保存する。ルビ・傍点はカクヨム式の記法のまま入っている
  • 原稿用紙のどのマスに何があるか、は保存しない。表示するたびに本文から割り付ける。設定を変えればすぐに割り付けが変わるのは、このため
  • 枚数も設定で変わるので保存しない。文字数は一覧に表示するため、保存のときに数えておく
  • 章ごとに1つの記録。1つの記録の上限は約1MB（日本語で約30万字）なので、25万字を超えたら章を分けるよう表示する

項目の詳しい定義は「詳細設計書」にあります。

6. 性能・安全性・費用の考え方

観点求めることどう実現しているか
性能10万字の章でも入力が遅れない変わった段落だけを割り付けし直す。原稿用紙は見えているページだけを描く
保存の確実さ通信が切れても文字が消えない書いた内容を先に端末の中へ保存し、つながったらサーバーへ送る
安全性持ち主だけが読み書きできるサーバー側のアクセス規則で、持ち主のアカウント以外を拒否する
費用月額0円Vercel・Firebase の無料の範囲で使う
保守AI で直し続けられる使う部品を最小限にし、原稿用紙の処理は自動テストで守る
