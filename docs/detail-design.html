1. 原稿用紙の割り付け

GENKO の中心となる処理です。「本文＋設定」を受け取り、「どの行のどのマスに何を置くか」を返します。画面とは切り離した処理なので、自動テストで正しさを確かめられます。

  1. 段落に分ける：本文を改行で区切る。記法は段落をまたがない
  2. 記法を読み取る：｜漢字《かんじ》 や 《《傍点》》 を見つけ、親文字とルビ、傍点の範囲を取り出す。記号そのものは表示しない
  3. 表示する文字の並びを作る：1文字ごとに「本文の何文字目か」を覚えておく（カーソルや削除に使う）
  4. マスにまとめる：「。」」のような句読点＋閉じ括弧を1マスに。2桁までの半角数字を1マスに
  5. 行に詰める：段落の頭に字下げのマスを入れ、行の字数で折り返す。その際に禁則処理（ぶら下げ・行末禁則）を行う
  6. ルビの位置を決める：親文字がどの行のどのマスにあるかから、ルビを置く位置を決める。親文字が2行にまたがるときは、ルビの文字を親文字の数に合わせて分ける

こうして作った行を、行数ごとに区切ったものがページです。マスの情報は保存せず、表示のたびに本文から作り直します。

3. 長い章を速く扱う工夫

1文字打つたびに本文全体を割り付けし直すと、長い章では時間がかかります（10万字で約30ミリ秒）。そこで次の工夫をしています。

  • 段落ごとに結果を覚えておく：割り付けの結果を段落の中身ごとに覚えておき、変わっていない段落は使い回す。行の位置は「段落の先頭から何文字目か」で持ち、使うときに本文全体での位置に直す。これで10万字でも1文字あたり約1ミリ秒になった
  • 見えているページだけを描く：原稿用紙モードでは、画面に見えているページとその前後1ページだけを画面に描く
  • 中身の変わらないページは描き直さない：ページの中身を要約しておき、前と同じなら描き直しを省く

4. マス目上のカーソル

カーソルの位置は「本文の何文字目か」で持ち、表示するときにマス目上の位置に直します。

  • 見えない文字を飛ばす：原稿用紙では ｜《》 とルビの文字が見えない。そのため ↑↓ は、表示されている文字の前後だけを移る。見えない文字の上でカーソルが止まって見えるのを防ぐ
  • ルビの外側に置く：ルビ付きの言葉の直前・直後にカーソルを置くと、記号の外側の位置になる。続けて打った文字が、ルビの中に入らない
  • 折り返しの境目：行の終わりと次の行の頭は、本文では同じ位置。ふつうは次の行の頭に表示するが、行末禁則で短くなった行の末尾へ ← → で移ったときは、その行に留まる
  • ← → の移動：隣の行の同じ高さのマスへ移る。短い行を通っても、元の高さを覚えておく

マス目上での削除

  • Backspace はカーソルの前の、表示されている1文字を消す。ルビの直後なら、親文字の最後の1文字を消す
  • 親文字（傍点の文字）が1文字だけのときは、記号ごとまとめて消す（記号だけが残らないように）
  • 段落の頭で Backspace を押すと、前の段落とつながる

5. 日本語入力（変換中の文字）の扱い

PC の原稿用紙モードでは、文字が透明で見えない入力欄をカーソルのマスに重ねて置き、日本語入力を受け取ります。表示はすべて GENKO が描くマス目で行います。

  1. 変換が始まると、変換中の文字を本文のカーソル位置に仮に差し込んだ状態で割り付けし直す
  2. 仮の文字は色付きで表示する。確定後と同じルールで割り付けるので、禁則なども含めて崩れない
  3. 確定すると、その文字を本当に本文に入れる
  4. 入力欄はカーソルの位置にあるので、変換候補の小窓も文字の近くに出る

6. 横書きモードの「書く表示」と「読む表示」

スマホでも日本語入力が安定するよう、横書きモードではブラウザのふつうの入力欄を使います。ふつうの入力欄では文字の上にルビを載せられないため、2つの表示を切り替えます。

表示いつ見え方
書く表示入力欄にカーソルがある間記法のまま（｜吾輩《わがはい》）
読む表示入力欄から離れたときルビ・傍点付き。段落の頭の字下げも反映

読む表示の各文字は「本文の何文字目か」を持っています。押した文字の位置を求めて入力欄に切り替え、その位置にカーソルを置きます。スマホでキーボードを出すため、この切り替えは押した操作の中ですぐに行います。

7. 自動保存と同期

決まり内容
保存するとき入力が止まってから2秒後。画面を離れる・章を切り替える・アプリを閉じるときは、待たずにすぐ
通信が切れているとき端末の中に保存され、表示は「オフライン（端末に保存）」。つながると自動で送られる
ほかの端末の変更サーバーから知らせが来たら表示を更新する。ただし、最後の入力から3秒以内（打っている最中）や、まだ保存していない内容があるときは書き換えない
自分の書いた変更まだサーバーに届いていない自分の変更の知らせは、無視する
同時に書いたとき章は保存するたびに「版の番号」と「保存した端末」を残す。ほかの端末が先に新しい版を保存していたのに、この端末でまだ保存していない変更があるとき、または同じ版の番号でほかの端末の保存が上書きしたときは、同時編集として保存を止め、どちらの版を残すかを選ばせる（両方を残すこともできる）。資料は後から保存したほうが残る
通信がないときアプリのファイルは端末にとっておく仕組み（service worker）で開ける。データは端末内の写しで読み書きし、つながったら送る。作品・章・資料を作るときも、通信の完了を待たずに先へ進む
保存に失敗したとき表示は「保存できませんでした」。次に打ったとき、または画面を離れるときに、もう一度保存する

8. 元に戻す・やり直し

  • ブラウザの入力欄の「元に戻す」は、プログラムで本文を書き換えると正しく動かなくなるため、GENKO が自分で履歴を持つ
  • 横書きと原稿用紙の両モードで、同じ履歴を使う。戻すと、カーソルも編集前の位置に戻る
  • 1秒より短い間隔で続けて打った文字は、まとめて1回で戻す。記号ボタンは1回ずつ戻す
  • 履歴は300回分まで。章を開き直したとき、ほかの端末の変更が反映されたときは、履歴を消す

9. 設定の2段階

実際に使う設定 ＝ すべての作品の既定値 ＋ 作品ごとの上書き（指定した項目だけ）
  • 作品の中から設定を開いたときは、「この作品だけに適用」と「すべての作品の既定値にする」を選べる
  • 「この作品だけ」を選んで変えると、その作品は表示中の値をすべて自分の設定として持つ。あとで既定値を変えても、その作品は変わらない
  • 字数・行数は 10〜40 に収める。おかしな値が保存されていても、読み込むときに直す

10. 保存データの項目

ユーザー（users/ユーザーID）

項目型内容
settings.cols数値1行の字数（既定 20）
settings.rows数値1枚の行数（既定 20）
settings.autoIndent真偽自動字下げ（既定 ON）
settings.presets一覧保存したプリセット（名前、字数、行数）
lastOpenedまとまり最後に開いた章（作品ID、章ID）
updatedAt日時更新日時

作品（…/works/作品ID）

項目型内容
title文字作品名
order数値作品一覧での並び順
settingsOverrideまとまり作品ごとに上書きした設定（指定した項目だけ）
createdAt・updatedAt日時作成日時・更新日時

章（…/works/作品ID/chapters/章ID）

項目型内容
title文字章タイトル
order数値作品の中での並び順
body文字本文（カクヨム式の記法を含むプレーンテキスト）
charCount数値文字数（B-10 の数え方）。一覧に表示するため、保存のときに数える
version・savedBy数値・文字保存するたびに増える版の番号と、保存した端末。同時編集の見分けに使う
updatedAt日時更新日時
  • 並べ替えは、隣どうしの order を入れ替えて行う
  • 作品を削除するときは、中の章もまとめて削除する（データベースは自動では消さないため）
  • 作品を作るときは、最初の章「第1話」も一緒に作る

資料フォルダ・資料・日ごとの文字数（フェーズ2）

場所主な項目
…/works/作品ID/folders/フォルダIDtitle（名前）、order（並び順）
…/works/作品ID/notes/資料IDfolderId（入っているフォルダ）、title、kind（プロット・キャラクター・メモ）、order、body（本文）
users/ユーザーID/dailyStats/日付added（その日に増えた文字数。本文を保存するたびに差を足す）

作品には目標（goal：字数または枚数）、設定には原稿用紙の見た目（罫線の色・背景・文字）、ページ送り、カクヨム用コピーの全角スペース、1日の目標も持ちます。

11. ファイルの形式

.txt の読み込み

  • ファイルの先頭の印（BOM）があれば、それに従う（UTF-8・UTF-16）
  • なければ UTF-8 として読み、読めない部分が1つでもあれば Shift_JIS として読み直す
  • 改行は統一し、1ファイルを1章にする。章タイトルはファイル名から拡張子を外したもの

.txt の書き出し

  • 文字コードは UTF-8。記法はカクヨム式のまま
  • 作品まとめての場合は、各章を「章タイトル、空行、本文」とし、章の間に空行を2つ入れる
  • ファイル名に使えない記号（\ / : * ? " < > |）は「_」に置き換える

バックアップ（.json）

{
  "app": "GENKO",
  "exportedAt": "2026-11-03T12:00:00+09:00",
  "settings": { "cols": 20, "rows": 20, "autoIndent": true, "presets": [] },
  "works": [
    {
      "title": "作品名",
      "order": 0,
      "settingsOverride": {},
      "chapters": [
        { "title": "第1話", "order": 0, "body": "本文…" }
      ]
    }
  ]
}

フェーズ2から、作品の中の資料フォルダ（folders）と資料（notes）もバックアップに入ります。

バックアップからの復元

  • 「新しい作品として追加する」：バックアップの作品を、いまある作品の後ろにすべて追加する
  • 「いまある作品を上書きする」：同じタイトルの作品の章・資料を、バックアップの内容に置き換える（実行の前に確認を出す）。同じタイトルの作品がなければ追加する
  • どちらでも、設定は変えない。資料がない古いバックアップも読める

カクヨム用コピー

  • 縦中横の ^ を外す。ルビ・傍点はカクヨムと同じ記法なので、そのまま
  • 設定によって、段落の頭に全角スペースを入れる（「 『 （ で始まる段落と、すでに全角空白で始まる段落には入れない）

12. アクセス規則

  • サーバー側の規則で、ログインしていて、かつ持ち主本人のアカウントのときだけ、持ち主のデータを読み書きできる。それ以外はすべて拒否する
  • アプリの側でも、持ち主以外のアカウントでログインしたら、すぐにログアウトさせる（画面の出し分けのため。データの保護そのものはサーバー側の規則が担う）
  • Google でのログインは、小さな画面（ポップアップ）を開く方式。iPhone の Safari では、画面を切り替える方式がプライバシー保護の機能で失敗することがあるため
